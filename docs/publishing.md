## 公開ソースを取り出す

既存の作業ディレクトリをそのまま公開せず、次の処理で許可したソースだけを空の別ディレクトリへコピーしてください。

```bash
npm run release:prepare -- /tmp/personal-context-mcp-public-source
```

コピー先の親ディレクトリは先に作成し、コピー先自体は存在しない状態にします。この処理は元ファイルを削除せず、Git履歴も変更しません。src・架空データのtests・ビルド設定・必要なスクリプト・汎用ガイドだけをコピーします。個人パス・メール・秘密鍵・代表的なトークンの既知パターンやシンボリックリンクを検出すると、内容を表示せず停止します。第三者由来の公開連絡先を含むlockfileはメール検査の対象外ですが、鍵やトークンは検査します。

この検査は網羅的な秘密情報検出ではありません。新しい公開候補やGit履歴が追加された場合は、専用スキャナーと目視確認を併用してください。

## 公開対象を選ぶ

過去の設計・HTMLレポート・ベンチマークには、個人環境の絶対パス、具体的なタスク名、実利用状況の記録が残っています。今回整理した4文書だけを確認して、リポジトリ全体が公開可能と判断しないでください。

| 対象                 | 確認する内容                                   |
| -------------------- | ---------------------------------------------- |
| docsの過去文書・HTML | 個人環境、実タスク、組織名、実利用ログ         |
| AGENTS.md            | 個人の指示書パスと内部運用                     |
| .idea・.hallmark     | 開発環境やデザイン作業のメタデータ             |
| tests・fixtures      | 実データ由来の識別子、公開すべきでない参照     |
| scripts              | 個人環境依存、認証情報、実サービスへの接続先   |
| package-lock.json    | registry URLや依存関係のライセンス             |
| .gitignore           | 秘密情報・個人設定を今後追加しても混入しないか |

.gitignoreは.env・秘密鍵の代表的な拡張子・IDE設定・内部指示書も除外します。既に追跡済みのファイルや、別名で保存された秘密情報は防げないため、公開ソースの許可リストと併用してください。

秘密情報らしい文字列の検索だけでは、秘密情報がないことを保証できません。履歴を含めた専用スキャンと、実データの目視確認を公開工程へ入れてください。

## 配布内容を検証する

`package.json` のCLIは `dist/server.js` と `dist/webServer.js` を参照します。distを含まない配布物では起動できません。Webの `dist/web-ui/index.html` とアセットも必要です。

公開対象が決まったら、標準ビルド後に以下を確認してください。

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run format:check
npm audit
npm pack
```

梱包結果に実データや不要な作業資料が入らず、実行ファイルとWebアセットが揃うことを確認します。梱包物を一時ディレクトリへ展開し、新しい保存先でMCP登録・Web表示・公開ツール取得を検証してください。
